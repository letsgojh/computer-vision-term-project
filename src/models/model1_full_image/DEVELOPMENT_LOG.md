# 모델 1 개발 과정 기록

모델 1은 중고거래 물건 사진이 **AI로 생성된 이미지인지** 판단합니다.
이 문서는 버전마다 어떤 구조를 썼고, 어떤 한계를 확인했고, 그래서 무엇을 바꿨는지를 기록합니다.
모든 수치는 실제 실행 결과이며, 출처 파일을 함께 적습니다.

---

## v0 — TIGAS + letterbox (2026-11-09 ~ 11-19)

### 구조

| 항목 | 내용 |
|---|---|
| 백본 | EfficientNet-B0 (`timm`, ImageNet 사전학습), 출력 1개(Fake logit) |
| 입력 | 이미지 전체를 384×384에 **letterbox**: 비율을 유지해 축소하고 남는 부분을 평균색으로 채움 |
| 데이터 | HF `H1merka/TIGAS_dataset`에서 2,000장, 6,000장 부분집합. 진짜는 주로 ImageNet, 가짜는 SD1.4/1.5/XL, Midjourney, GAN 등 19개 출처 |
| 임계값 | 검증 F1이 최대가 되는 값 1개 |
| 설명 | Grad-CAM (`explain.py`) |

### 결과

| 실험 | 테스트 데이터 | Accuracy | F1 | ROC-AUC |
|---|---|---|---|---|
| TIGAS 2,000장 | TIGAS test 200장 | 0.840 | 0.838 | 0.911 |
| TIGAS 6,000장 | TIGAS test 1,000장 | 0.912 | 0.913 | **0.972** |
| TIGAS 6,000장 | FraudBench (실제 상품 사진 vs AI 편집 사진) 200장 | 0.500 | 0.091 | **0.423** |
| TIGAS 6,000장 | FraudBench 진짜 20장 / AI 180장 | 0.125 | 0.064 | 0.507 |

출처: 구 작업 폴더의 `outputs/tigas_training_*/predictions/test_metrics.json`, `outputs/external_market/*/FraudBench/test_metrics.json`

### 확인한 한계

1. **같은 데이터셋 안에서만 잘 맞음.** TIGAS 테스트 AUC는 0.97인데, 상품 사진(FraudBench)에서는 0.42~0.51로 무작위 수준이었습니다. AI 이미지의 재현율도 3~5%까지 떨어졌습니다. 중고거래 사진에는 사실상 쓸 수 없는 상태였습니다.
2. **크기·비율 지름길(shortcut).** TIGAS에서 정사각형 이미지는 진짜의 17%(512/3000), 가짜의 89%(2675/3000)였습니다. letterbox는 정사각형이 아닌 이미지에만 회색 띠를 만듭니다. 그래서 모델이 그림 내용이 아니라 "띠가 있으면 진짜"라는 규칙을 배울 수 있는 구조였습니다. 같은 데이터셋 테스트에서는 이 규칙이 그대로 통하므로 점수가 부풀려집니다.
3. **구세대 생성기.** TIGAS의 생성기는 SD1.x와 GAN 중심이라, 최근 생성기(SD3, DALL·E 3, Midjourney v6)에 대한 검증이 없었습니다.
4. **진짜 이미지 도메인.** ImageNet 사진은 중고거래 사진과 촬영 방식이 다릅니다.
5. **임계값 하나로 판정.** 미탐(AI를 진짜로 통과)이 더 위험한 서비스인데, F1 기준 임계값 하나로는 이 우선순위를 반영할 수 없었습니다.

## v1 — Defactify + 원본 해상도 크롭 + 생성기 hold-out (2026-11-23 ~)

### 바꾼 점과 이유

| v0의 한계 | v1의 변경 | 구현 위치 |
|---|---|---|
| 같은 데이터셋 점수만 높음 | 학습에 쓰지 않은 **생성기**와 **데이터셋**으로 따로 평가. Defactify에서 DALL·E 3와 Midjourney v6는 테스트 전용, TIGAS 6,000장은 교차 테스트 전용 | `scripts/prepare_defactify.py`, `scripts/analyze_generalization.py`, `configs/model1_tigas_crosstest.yaml` |
| 크기·비율 지름길 | 학습 전에 **메타데이터만으로 맞히는 기준선**을 측정. 입력은 letterbox 대신 **원본 해상도에서 256×256을 잘라냄**(패딩·확대 흔적 없음). 학습 시 진짜와 가짜에 똑같이 무작위 축소와 JPEG 재압축 적용 | `scripts/audit_shortcuts.py`, `dataset.py`의 `NativeCropTransform` |
| 구세대 생성기 | Defactify: SD2.1, SDXL, SD3, DALL·E 3, Midjourney v6 (진짜는 MS COCO) | `configs/model1_defactify.yaml` |
| 임계값 하나 | **3단계 판정**: 통과 / 의심 / AI. 의심 경계는 검증 AI 재현율 95%, AI 경계는 진짜 오탐률 1%로 계산. `thresholds.json`과 데모 슬라이더로 수시 조정 | `thresholds.py`, `scripts/calibrate_thresholds.py` |
| 사진 일부만 봄(크롭의 부작용) | 추론 시 사진을 짧은 변 512로 맞추고 겹치는 크롭으로 **전체를 덮어** 점수를 평균. 크롭별 Grad-CAM을 이어 붙여 사진 전체 히트맵 생성 | `inference.py` |
| 데모 없음 | Gradio 데모: 확률, 3단계 판정, AI 판정 시 히트맵, 임계값 저장 | `app/model1_demo.py` |

백본(EfficientNet-B0)은 바꾸지 않았습니다. v0의 문제는 모델 용량이 아니라 데이터와 전처리에 있었기 때문에, 원인을 분리해서 확인하려고 한 번에 한 요소씩 바꿨습니다.

### 학습 전 지름길 검사 (v1 데이터)

Defactify에서도 같은 문제가 있었습니다. 진짜(COCO)는 640×480처럼 비율이 제각각이고, 가짜는 생성기마다 크기가 고정된 정사각형입니다(SD2.1 768, SDXL·SD3 1024, DALL·E 3 270, Midjourney 436).
픽셀을 전혀 보지 않고 폭, 높이, 비율, 파일 크기, JPEG 양자화 테이블만으로 학습한 분류기의 테스트 AUC는 다음과 같습니다.

| 검사 | AUC |
|---|---|
| "정사각형인가" 한 가지만 사용 | 0.990 |
| 메타데이터 분류기, 학습 생성기(SD2.1/SDXL/SD3) | 1.000 |
| 메타데이터 분류기, hold-out 생성기(DALL·E 3 / MJ) | 0.735 (0.984 / 0.488) |
| JPEG 양자화 테이블 | 0.500 (모든 출처가 동일, 단서 없음) |

출처: `outputs/model1/shortcut_audit/shortcut_audit.json`

즉 v0 방식(letterbox)으로 Defactify를 학습했다면, 그림을 보지 않고도 거의 만점이 나왔을 것입니다.
v1의 CNN 점수는 이 기준선보다 높아야 하고, 특히 **크기를 맞춘 조건**(모든 이미지의 짧은 변을 512로 통일, `evaluate.py --eval-resize-short 512`)에서도 유지되어야 의미가 있습니다.

### 학습

- 데이터: train 진짜 6,933장 / 가짜 6,921장(SD2.1·SDXL·SD3 각 2,307장), val 진짜 1,467장 / 가짜 1,471장. 여러 split에 걸친 캡션 458행은 누수 방지를 위해 제거했습니다.
- 설정: 256×256 크롭, batch 64, AdamW lr 3e-4, 15 epoch, CUDA AMP. epoch당 약 3~4분 (RTX 4070 SUPER).
- 최적 epoch 14: **검증 F1 0.986, 검증 AUC 0.999**

출처: `outputs/model1/defactify_native_crop/logs/training.csv`, `outputs/model1/defactify_native_crop/defactify_train.log`

v0와 비교한 성과:
- 학습 생성기 테스트 AUC 0.949는 메타데이터만 쓴 기준선(1.000)보다 낮습니다. 하지만 v1 모델은 크기·비율 정보를 쓸 수 없는 구조라서, 이 점수는 픽셀 내용으로 얻은 것입니다.
- 크기를 맞춘 조건에서도 AUC가 0.86~0.91로 유지되어, 크기 지름길에 의존하지 않는다는 것을 확인했습니다. hold-out 생성기 AUC는 0.859에서 0.860으로 거의 그대로였습니다.

### v1에서 새로 확인한 한계

**1. 검증과 테스트의 큰 차이: 노이즈 지름길.**
같은 생성기인데 AI 재현율이 검증 95%에서 테스트 62%로 떨어졌습니다. 원인을 다음 순서로 확인했습니다.

- 진짜 이미지가 split 사이에 겹치는지 확인했습니다. 파일 MD5와 16×16 평균 해시 모두에서 train과 val, train과 test가 사실상 겹치지 않았습니다(0~2장). 해상도도 split마다 같았습니다. 누수가 원인은 아닙니다.
- 테스트 가짜의 점수는 두 덩어리로 나뉩니다. 중앙값은 0.995인데 약 20%가 0.1 미만이었습니다. 검증 가짜는 거의 모두 1.0 근처입니다.
- 256×256 중앙 크롭의 고주파 에너지 비율(반경 96 이상)을 각 생성기당 80장씩 측정했습니다.

| 그룹 | SD2.1 | SD3 | SDXL |
|---|---|---|---|
| 학습 가짜 | 0.192 | 0.181 | 0.139 |
| 검증 가짜 | 0.192 | 0.179 | 0.143 |
| 테스트 가짜, 점수 높음(>0.99) | 0.200 | 0.194 | 0.160 |
| 테스트 가짜, 점수 낮음(<0.1) | **0.252** | **0.255** | **0.252** |
| 진짜(COCO) 테스트 | 0.274 | | |

- 점수가 낮은 테스트 가짜를 확대해 보면 입자 노이즈가 뚜렷합니다. 테스트셋의 일부 가짜에는 노이즈나 샤프닝 같은 추가 처리가 되어 있는 것으로 보이고, 학습·검증셋에는 이런 이미지가 없습니다. 이 처리가 데이터셋의 의도된 설계인지는 확인하지 못했습니다.
- 결론적으로 모델은 "매끈하면 AI, 노이즈가 있으면 진짜"를 배웠습니다. AI 이미지에 노이즈만 넣으면 통과할 수 있으므로, 미탐을 가장 위험하게 보는 이 서비스에는 치명적인 지름길입니다.

**2. hold-out 생성기 재현율이 낮음.** 원본 해상도에서 DALL·E 3는 8.9%, Midjourney v6는 36.5%만 잡았습니다. 학습에 없던 생성기로는 아직 일반화되지 않았습니다.

**3. 크기 맞춤 조건에서 진짜 오탐률 증가.** 짧은 변을 512로 맞추자 진짜 오탐률이 0.5%에서 4.6%로 올랐습니다. COCO 진짜(짧은 변 약 480)는 확대되면서 리샘플링 흔적이 생깁니다. 데모도 사진을 짧은 변 512로 맞추므로, 이 영향을 받을 수 있습니다.

**4. 임계값 계산 오류.** 검증셋에서 모델이 너무 잘 맞아서, 재현율 95% 임계값(0.948)이 오탐률 1% 임계값보다 높게 나왔습니다. 그러자 "의심"과 "AI" 임계값이 같아져서 의심 구간이 사라졌습니다.

**5. TIGAS 교차 테스트 미실행 → 실행 후 결과.** 처음에는 TIGAS 메타데이터에 누수 검사용 `caption_id` 열이 없어서 평가가 중단됐습니다. 열을 추가한 뒤 실행했습니다. 데이터는 학습에 한 번도 쓰지 않은 6,000장입니다(진짜 3,000장, 대부분 ImageNet).

- 전체 AUC는 0.784였습니다.
- 진짜 판정: 통과 68.0%, 의심 13.4%, **AI 18.6%**. Defactify 진짜(COCO)의 AI 오탐률 1.0%보다 훨씬 높아서, 진짜 사진의 도메인이 바뀌면 오탐이 크게 늘어납니다.
- 생성기별 AUC는 다음과 같았습니다.
  - 확산 모델은 대체로 잘 잡았습니다. SDXL 0.963, Midjourney 0.933, DALL·E 2 0.923, SD1.4 0.889, SD1.5 0.87~0.88.
  - GAN과 구형 모델은 못 잡았습니다. ADM 0.636, VQDM 0.584, BigGAN 0.538, GauGAN 0.418.
  - GAN은 학습 데이터(전부 확산 모델)에 없는 계열이고, 중고거래 사진 생성에 쓰일 가능성도 낮아서 우선순위는 낮습니다.
- v0(TIGAS로 학습)의 TIGAS 테스트 AUC 0.972와 직접 비교할 수는 없습니다. v0는 같은 데이터셋 안의 평가이고, v1은 데이터셋 밖 평가이기 때문입니다.

출처: `outputs/model1/defactify_native_crop/eval_tigas/generalization.json`

### 그 밖의 한계

- hold-out 생성기는 원본 해상도가 낮아(270, 436px) 크롭 안의 물체 크기가 학습 데이터와 다릅니다. hold-out 점수에는 이 차이의 영향이 섞여 있을 수 있습니다.
- 진짜 이미지가 여전히 COCO 장면 사진입니다. 팀원이 직접 찍은 중고거래 사진으로 최종 확인이 필요합니다.
- Grad-CAM은 모델이 주목한 영역이지, 생성·조작된 위치의 증거가 아닙니다.

### v1.1 — 데모용 수정 (2026-11-23, 재학습 없음)

팀원 시연을 위해, 모델은 그대로 두고 판정과 시각화만 고쳤습니다.

| 문제 | 수정 | 결과 |
|---|---|---|
| 임계값이 0.948 하나로 합쳐져 "의심" 단계가 사라짐 | 의심 = min(재현율 95% 임계값, 진짜 오탐률 5% 임계값), AI = 진짜 오탐률 1% 임계값 | 의심 0.060, AI 0.745 (검증 기준 의심 이상: AI 재현율 99.7%, 진짜 오탐률 5.0% / AI 판정: AI 재현율 98.1%, 진짜 오탐률 1.0%) |
| 히트맵에 조각 경계 이음매 (256px 조각을 겹침 없이 나눔) | 조각을 겹치게 배치. 그래도 격자 무늬가 남아서, 조각 가장자리로 갈수록 가중치를 줄이는 Hann 창으로 섞음 | 이음매 제거 |
| 데모 화면에서 모델 버전을 알 수 없음 | 데모 상단에 버전, epoch, 개발 기록 위치 표시 (`--version`) | |

새 임계값을 적용한 테스트 결과입니다(원본 해상도).
- 진짜 판정 비율: 통과 95.3%, 의심 3.7%, AI 1.0%
- 학습 생성기 AI 재현율: 의심 이상 81.1%, AI 판정 69.8%
- hold-out 생성기 AI 재현율: 의심 이상 53.1%, AI 판정 31.6%

데모 조건(짧은 변 512)에서는 진짜의 21.1%가 의심 이상으로 판정됩니다(의심 13.3%, AI 7.9%). 실제 사진이 자주 "의심"으로 나올 수 있다는 뜻이므로, 시연할 때 이 한계를 함께 설명해야 합니다.

## v2 — 노이즈·블러·샤프닝 증강 (2026-11-23 ~)

### 바꾼 점과 이유

v1은 "매끈하면 AI, 입자 노이즈가 있으면 진짜"라는 지름길을 배웠습니다(v1 한계 1). v2는 이 단서를 지우기 위해 학습할 때 다음 처리를 진짜와 가짜에 **같은 확률로** 적용합니다. 그러면 노이즈 양으로는 라벨을 맞힐 수 없게 됩니다.

| 증강 | 확률 | 강도 |
|---|---|---|
| 가우시안 블러 | 0.2 | 반경 0.3~1.5 |
| 언샤프 마스크 (블러를 안 했을 때만) | 0.2 | 반경 1~2, 50~150% |
| 가우시안 노이즈 | 0.3 | σ 2~10 (0~255 기준) |

나머지(데이터, 모델, 크롭, 학습 설정)는 v1과 같습니다. 바꾼 요소가 증강 하나뿐이라, 결과 차이를 이 변경의 효과로 해석할 수 있습니다.

- 설정: `configs/model1_defactify_v2.yaml`
- 구현: `dataset.py`의 `NativeCropTransform`. 새 증강의 기본값은 0이라 v1 설정은 이전과 똑같이 동작합니다.

### 학습

- 15 epoch를 끝까지 학습했고, 최적 epoch는 14입니다. 검증 F1 0.979로 v1(0.986)보다 약간 낮은데, 증강 때문에 학습 데이터가 더 어려워졌기 때문으로 보입니다.
- 임계값은 v1.1 규칙으로 다시 계산했습니다. 의심 0.220, AI 0.912입니다.
  - 검증셋 기준 의심 이상: AI 재현율 99.0%, 진짜 오탐률 5.0%
  - 검증셋 기준 AI 판정: AI 재현율 94.5%, 진짜 오탐률 1.0%

출처: `outputs/model1/defactify_v2_noise_aug/logs/training.csv`, `thresholds.json`

### 결과: v1과 비교

각 버전은 자기 임계값을 씁니다(v1: 0.060 / 0.745, v2: 0.220 / 0.912). 의심 이상과 AI 판정 열은 AI 재현율입니다.

| 평가 | v1 AUC | v2 AUC | v1 의심 이상 | v2 의심 이상 | v1 AI 판정 | v2 AI 판정 |
|---|---|---|---|---|---|---|
| Defactify 학습 생성기 (원본 해상도) | 0.949 | **0.992** | 81.1% | **95.9%** | 69.8% | **83.0%** |
| Defactify hold-out 생성기 (원본 해상도) | 0.859 | **0.923** | 53.1% | **63.0%** | 31.6% | **33.7%** |
| └ DALL·E 3 | 0.814 | 0.897 | 40.0% | 51.3% | 17.2% | 20.6% |
| └ Midjourney v6 | 0.903 | 0.949 | 66.1% | 74.6% | 45.9% | 46.8% |
| Defactify 학습 생성기 (크기 맞춤 512) | 0.908 | **0.953** | 84.5% | **94.4%** | 71.7% | **81.9%** |
| Defactify hold-out 생성기 (크기 맞춤 512) | 0.860 | **0.875** | 77.7% | **80.0%** | 55.8% | 56.1% |
| TIGAS 교차 테스트 | **0.784** | 0.754 | **73.8%** | 67.9% | **56.6%** | 52.5% |

진짜 사진의 판정 비율(통과 / 의심 / AI)은 다음과 같습니다.

|---|---|---|
| Defactify (원본 해상도) | 95.3 / 3.7 / 1.0% | 94.9 / 4.3 / 0.9% |

### 노이즈 지름길이 해결됐는지 확인

v1이 점수 0.1 미만으로 놓친 학습 생성기 가짜 886장(전체 4,408장 중 20.1%)을 v2로 다시 채점했습니다. 이 이미지들은 v1 분석에서 입자 노이즈가 섞여 있던 그룹입니다.

- v2 점수 중앙값은 0.975였습니다.
- 87.0%가 의심 이상, 60.9%가 AI로 판정됐습니다.
- 점수가 0.1 미만인 가짜의 비율은 20.1%에서 **2.4%**로 줄었습니다.

노이즈 지름길은 대부분 해결됐습니다.

### 해석

- **좋아진 점**: Defactify에서는 모든 지표가 좋아졌습니다. 특히 hold-out 생성기 AUC가 0.859에서 0.923으로 오른 것은, 노이즈 단서를 지우자 학습하지 않은 생성기에서도 더 일반적인 흔적을 쓰게 됐다는 뜻으로 해석할 수 있습니다.
- **나빠진 점**: TIGAS 교차 테스트의 AUC는 0.784에서 0.754로 조금 떨어졌습니다. 다만 진짜를 AI로 잘못 판정하는 비율도 18.6%에서 15.6%로 줄었습니다. TIGAS의 상당 부분은 학습에 없던 GAN 계열이라, 이번 변경의 목표 범위 밖입니다.
- **결정**: 미탐을 줄이는 것이 목표이고 Defactify의 개선 폭이 훨씬 크므로, **데모를 v2로 교체**했습니다.

### 남은 한계

- hold-out 생성기의 AI 판정 재현율은 34%입니다. 학습하지 않은 생성기는 대부분 "의심"까지만 잡힙니다.
- 데모 조건(짧은 변 512)에서는 진짜의 23%가 의심 이상으로 판정됩니다.
- 진짜 사진이 COCO와 ImageNet이라, 실제 중고거래 사진(폰 촬영)으로는 아직 체계적으로 평가하지 않았습니다. 팀원 사진 평가가 필요합니다.
- GAN 계열(BigGAN, GauGAN 등)은 탐지하지 못합니다.

### 실사용 테스트: 직접 찍은 폰 사진 (2026-11-23)

데모에 직접 찍은 사진을 올리자 AI 확률 73.6%가 나왔습니다. 사용 가능 기준은 **"직접 찍은 사진은 AI 확률 30% 미만"**으로 정했습니다.

이 기준으로 iPhone 15로 촬영한 진짜 사진 120장(이어버드, 노트북, 스마트폰, 스마트워치 각 30장, 5712×4284)을 모두 채점했습니다. 작업 해상도(짧은 변)를 바꿔 가며 측정했습니다.

| 모델 | 짧은 변 | AI 확률 중앙값 | 30% 미만 비율 | 50% 이상 비율 |
|---|---|---|---|---|
| v1 | 512 (데모) | 0.809 | 2.5% | 90.0% |
| v1 | 원본 | 0.945 | 0% | 100% |
| v2 | 512 (데모) | 0.730 | **5.0%** | 83.3% |
| v2 | 1024 | 0.866 | 0% | 97.5% |
| v2 | 2048 | 0.923 | 0% | 100% |
| v2 | 원본 | 0.949 | 0% | 100% |

출처: `$CVTP_DATA_ROOT/samples/phone_scores.csv` (로컬 전용, 사진과 함께 Git에서 제외)

**결론: 기준 미달, 사실상 사용 불가.**
- 진짜 폰 사진의 95%를 30% 이상으로 판정했습니다.
- 처음에는 데모의 강한 축소(약 8배)가 원인일 것으로 추정했습니다. 그런데 측정해 보니 반대로, 해상도를 높일수록 점수가 올라갔습니다. 원본 해상도에서는 중앙값이 0.949였습니다.
- 모델은 "AI 이미지인가"보다 "**COCO 같은 옛날 웹 사진인가**"를 배운 것으로 보입니다. 학습한 진짜 클래스가 COCO(2014년 무렵 640×480 웹 JPEG) 하나뿐이라, 요즘 폰 사진처럼 다른 진짜 사진은 모두 "진짜 아님" 쪽으로 밀립니다.
- 크기, 노이즈에 이어 세 번째 지름길로, 이번에는 **진짜 사진의 출처** 자체입니다. Defactify와 TIGAS 테스트 점수는 이 문제를 드러내지 못했습니다. 두 테스트의 진짜도 같은 종류의 웹 사진이기 때문입니다.
