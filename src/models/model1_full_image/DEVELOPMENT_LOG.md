# 모델 1 개발 과정 기록

모델 1은 중고거래 물건 사진이 **AI로 생성된 이미지인지** 판단합니다.
이 문서는 버전마다 어떤 구조를 썼고, 어떤 한계를 확인했고, 그래서 무엇을 바꿨는지를 기록합니다.
모든 수치는 실제 실행 결과이며, 출처 파일을 함께 적습니다.

---

## v0 — TIGAS + letterbox (2026-11-09 ~ 11-19)

### 구조

| 항목 | 내용 |
|---|---|
| 백본 | EfficientNet-B0 (`timm`, ImageNet 사전학습), 출력 1개(Fake logit) |
| 입력 | 이미지 전체를 384×384에 **letterbox**: 비율을 유지해 축소하고 남는 부분을 평균색으로 채움 |
| 데이터 | HF `H1merka/TIGAS_dataset`에서 2,000장, 6,000장 부분집합. 진짜는 주로 ImageNet, 가짜는 SD1.4/1.5/XL, Midjourney, GAN 등 19개 출처 |
| 임계값 | 검증 F1이 최대가 되는 값 1개 |
| 설명 | Grad-CAM (`explain.py`) |

### 결과

| 실험 | 테스트 데이터 | Accuracy | F1 | ROC-AUC |
|---|---|---|---|---|
| TIGAS 2,000장 | TIGAS test 200장 | 0.840 | 0.838 | 0.911 |
| TIGAS 6,000장 | TIGAS test 1,000장 | 0.912 | 0.913 | **0.972** |
| TIGAS 6,000장 | FraudBench (실제 상품 사진 vs AI 편집 사진) 200장 | 0.500 | 0.091 | **0.423** |
| TIGAS 6,000장 | FraudBench 진짜 20장 / AI 180장 | 0.125 | 0.064 | 0.507 |

출처: 구 작업 폴더의 `outputs/tigas_training_*/predictions/test_metrics.json`, `outputs/external_market/*/FraudBench/test_metrics.json`

### 확인한 한계

1. **같은 데이터셋 안에서만 잘 맞음.** TIGAS 테스트 AUC는 0.97인데, 상품 사진(FraudBench)에서는 0.42~0.51로 무작위 수준이었습니다. AI 이미지의 재현율도 3~5%까지 떨어졌습니다. 중고거래 사진에는 사실상 쓸 수 없는 상태였습니다.
2. **크기·비율 지름길(shortcut).** TIGAS에서 정사각형 이미지는 진짜의 17%(512/3000), 가짜의 89%(2675/3000)였습니다. letterbox는 정사각형이 아닌 이미지에만 회색 띠를 만듭니다. 그래서 모델이 그림 내용이 아니라 "띠가 있으면 진짜"라는 규칙을 배울 수 있는 구조였습니다. 같은 데이터셋 테스트에서는 이 규칙이 그대로 통하므로 점수가 부풀려집니다.
3. **구세대 생성기.** TIGAS의 생성기는 SD1.x와 GAN 중심이라, 최근 생성기(SD3, DALL·E 3, Midjourney v6)에 대한 검증이 없었습니다.
4. **진짜 이미지 도메인.** ImageNet 사진은 중고거래 사진과 촬영 방식이 다릅니다.
5. **임계값 하나로 판정.** 미탐(AI를 진짜로 통과)이 더 위험한 서비스인데, F1 기준 임계값 하나로는 이 우선순위를 반영할 수 없었습니다.

## v1 — Defactify + 원본 해상도 크롭 + 생성기 hold-out (2026-11-23 ~)

### 바꾼 점과 이유

| v0의 한계 | v1의 변경 | 구현 위치 |
|---|---|---|
| 같은 데이터셋 점수만 높음 | 학습에 쓰지 않은 **생성기**와 **데이터셋**으로 따로 평가. Defactify에서 DALL·E 3와 Midjourney v6는 테스트 전용, TIGAS 6,000장은 교차 테스트 전용 | `scripts/prepare_defactify.py`, `scripts/analyze_generalization.py`, `configs/model1_tigas_crosstest.yaml` |
| 크기·비율 지름길 | 학습 전에 **메타데이터만으로 맞히는 기준선**을 측정. 입력은 letterbox 대신 **원본 해상도에서 256×256을 잘라냄**(패딩·확대 흔적 없음). 학습 시 진짜와 가짜에 똑같이 무작위 축소와 JPEG 재압축 적용 | `scripts/audit_shortcuts.py`, `dataset.py`의 `NativeCropTransform` |
| 구세대 생성기 | Defactify: SD2.1, SDXL, SD3, DALL·E 3, Midjourney v6 (진짜는 MS COCO) | `configs/model1_defactify.yaml` |
| 임계값 하나 | **3단계 판정**: 통과 / 의심 / AI. 의심 경계는 검증 AI 재현율 95%, AI 경계는 진짜 오탐률 1%로 계산. `thresholds.json`과 데모 슬라이더로 수시 조정 | `thresholds.py`, `scripts/calibrate_thresholds.py` |
| 사진 일부만 봄(크롭의 부작용) | 추론 시 사진을 짧은 변 512로 맞추고 겹치는 크롭으로 **전체를 덮어** 점수를 평균. 크롭별 Grad-CAM을 이어 붙여 사진 전체 히트맵 생성 | `inference.py` |
| 데모 없음 | Gradio 데모: 확률, 3단계 판정, AI 판정 시 히트맵, 임계값 저장 | `app/model1_demo.py` |

백본(EfficientNet-B0)은 바꾸지 않았습니다. v0의 문제는 모델 용량이 아니라 데이터와 전처리에 있었기 때문에, 원인을 분리해서 확인하려고 한 번에 한 요소씩 바꿨습니다.

### 학습 전 지름길 검사 (v1 데이터)

Defactify에서도 같은 문제가 있었습니다. 진짜(COCO)는 640×480처럼 비율이 제각각이고, 가짜는 생성기마다 크기가 고정된 정사각형입니다(SD2.1 768, SDXL·SD3 1024, DALL·E 3 270, Midjourney 436).
픽셀을 전혀 보지 않고 폭, 높이, 비율, 파일 크기, JPEG 양자화 테이블만으로 학습한 분류기의 테스트 AUC는 다음과 같습니다.

| 검사 | AUC |
|---|---|
| "정사각형인가" 한 가지만 사용 | 0.990 |
| 메타데이터 분류기, 학습 생성기(SD2.1/SDXL/SD3) | 1.000 |
| 메타데이터 분류기, hold-out 생성기(DALL·E 3 / MJ) | 0.735 (0.984 / 0.488) |
| JPEG 양자화 테이블 | 0.500 (모든 출처가 동일, 단서 없음) |

출처: `outputs/model1/shortcut_audit/shortcut_audit.json`

즉 v0 방식(letterbox)으로 Defactify를 학습했다면, 그림을 보지 않고도 거의 만점이 나왔을 것입니다.
v1의 CNN 점수는 이 기준선보다 높아야 하고, 특히 **크기를 맞춘 조건**(모든 이미지의 짧은 변을 512로 통일, `evaluate.py --eval-resize-short 512`)에서도 유지되어야 의미가 있습니다.

### 학습

- 데이터: train 진짜 6,933장 / 가짜 6,921장(SD2.1·SDXL·SD3 각 2,307장), val 진짜 1,467장 / 가짜 1,471장. 여러 split에 걸친 캡션 458행은 누수 방지를 위해 제거했습니다.
- 설정: 256×256 크롭, batch 64, AdamW lr 3e-4, 15 epoch, CUDA AMP. epoch당 약 3~4분 (RTX 4070 SUPER).
- 최적 epoch 14: **검증 F1 0.986, 검증 AUC 0.999**

출처: `outputs/model1/defactify_native_crop/logs/training.csv`, `outputs/model1/defactify_native_crop/defactify_train.log`

v0와 비교한 성과:
- 학습 생성기 테스트 AUC 0.949는 메타데이터만 쓴 기준선(1.000)보다 낮습니다. 하지만 v1 모델은 크기·비율 정보를 쓸 수 없는 구조라서, 이 점수는 픽셀 내용으로 얻은 것입니다.
- 크기를 맞춘 조건에서도 AUC가 0.86~0.91로 유지되어, 크기 지름길에 의존하지 않는다는 것을 확인했습니다. hold-out 생성기 AUC는 0.859에서 0.860으로 거의 그대로였습니다.

### v1에서 새로 확인한 한계

**1. 검증과 테스트의 큰 차이: 노이즈 지름길.**
같은 생성기인데 AI 재현율이 검증 95%에서 테스트 62%로 떨어졌습니다. 원인을 다음 순서로 확인했습니다.

- 진짜 이미지가 split 사이에 겹치는지 확인했습니다. 파일 MD5와 16×16 평균 해시 모두에서 train과 val, train과 test가 사실상 겹치지 않았습니다(0~2장). 해상도도 split마다 같았습니다. 누수가 원인은 아닙니다.
- 테스트 가짜의 점수는 두 덩어리로 나뉩니다. 중앙값은 0.995인데 약 20%가 0.1 미만이었습니다. 검증 가짜는 거의 모두 1.0 근처입니다.
- 256×256 중앙 크롭의 고주파 에너지 비율(반경 96 이상)을 각 생성기당 80장씩 측정했습니다.

| 그룹 | SD2.1 | SD3 | SDXL |
|---|---|---|---|
| 학습 가짜 | 0.192 | 0.181 | 0.139 |
| 검증 가짜 | 0.192 | 0.179 | 0.143 |
| 테스트 가짜, 점수 높음(>0.99) | 0.200 | 0.194 | 0.160 |
| 테스트 가짜, 점수 낮음(<0.1) | **0.252** | **0.255** | **0.252** |
| 진짜(COCO) 테스트 | 0.274 | | |

- 점수가 낮은 테스트 가짜를 확대해 보면 입자 노이즈가 뚜렷합니다. 테스트셋의 일부 가짜에는 노이즈나 샤프닝 같은 추가 처리가 되어 있는 것으로 보이고, 학습·검증셋에는 이런 이미지가 없습니다. 이 처리가 데이터셋의 의도된 설계인지는 확인하지 못했습니다.
- 결론적으로 모델은 "매끈하면 AI, 노이즈가 있으면 진짜"를 배웠습니다. AI 이미지에 노이즈만 넣으면 통과할 수 있으므로, 미탐을 가장 위험하게 보는 이 서비스에는 치명적인 지름길입니다.

**2. hold-out 생성기 재현율이 낮음.** 원본 해상도에서 DALL·E 3는 8.9%, Midjourney v6는 36.5%만 잡았습니다. 학습에 없던 생성기로는 아직 일반화되지 않았습니다.

**3. 크기 맞춤 조건에서 진짜 오탐률 증가.** 짧은 변을 512로 맞추자 진짜 오탐률이 0.5%에서 4.6%로 올랐습니다. COCO 진짜(짧은 변 약 480)는 확대되면서 리샘플링 흔적이 생깁니다. 데모도 사진을 짧은 변 512로 맞추므로, 이 영향을 받을 수 있습니다.

**4. 임계값 계산 오류.** 검증셋에서 모델이 너무 잘 맞아서, 재현율 95% 임계값(0.948)이 오탐률 1% 임계값보다 높게 나왔습니다. 그러자 "의심"과 "AI" 임계값이 같아져서 의심 구간이 사라졌습니다.

**5. TIGAS 교차 테스트 미실행 → 실행 후 결과.** 처음에는 TIGAS 메타데이터에 누수 검사용 `caption_id` 열이 없어서 평가가 중단됐습니다. 열을 추가한 뒤 실행했습니다. 데이터는 학습에 한 번도 쓰지 않은 6,000장입니다(진짜 3,000장, 대부분 ImageNet).

- 전체 AUC는 0.784였습니다.
- 진짜 판정: 통과 68.0%, 의심 13.4%, **AI 18.6%**. Defactify 진짜(COCO)의 AI 오탐률 1.0%보다 훨씬 높아서, 진짜 사진의 도메인이 바뀌면 오탐이 크게 늘어납니다.
- 생성기별 AUC는 다음과 같았습니다.
  - 확산 모델은 대체로 잘 잡았습니다. SDXL 0.963, Midjourney 0.933, DALL·E 2 0.923, SD1.4 0.889, SD1.5 0.87~0.88.
  - GAN과 구형 모델은 못 잡았습니다. ADM 0.636, VQDM 0.584, BigGAN 0.538, GauGAN 0.418.
  - GAN은 학습 데이터(전부 확산 모델)에 없는 계열이고, 중고거래 사진 생성에 쓰일 가능성도 낮아서 우선순위는 낮습니다.
- v0(TIGAS로 학습)의 TIGAS 테스트 AUC 0.972와 직접 비교할 수는 없습니다. v0는 같은 데이터셋 안의 평가이고, v1은 데이터셋 밖 평가이기 때문입니다.

출처: `outputs/model1/defactify_native_crop/eval_tigas/generalization.json`

### 그 밖의 한계

- hold-out 생성기는 원본 해상도가 낮아(270, 436px) 크롭 안의 물체 크기가 학습 데이터와 다릅니다. hold-out 점수에는 이 차이의 영향이 섞여 있을 수 있습니다.
- 진짜 이미지가 여전히 COCO 장면 사진입니다. 팀원이 직접 찍은 중고거래 사진으로 최종 확인이 필요합니다.
- Grad-CAM은 모델이 주목한 영역이지, 생성·조작된 위치의 증거가 아닙니다.

### v1.1 — 데모용 수정 (2026-11-23, 재학습 없음)

팀원 시연을 위해, 모델은 그대로 두고 판정과 시각화만 고쳤습니다.

| 문제 | 수정 | 결과 |
|---|---|---|
| 임계값이 0.948 하나로 합쳐져 "의심" 단계가 사라짐 | 의심 = min(재현율 95% 임계값, 진짜 오탐률 5% 임계값), AI = 진짜 오탐률 1% 임계값 | 의심 0.060, AI 0.745 (검증 기준 의심 이상: AI 재현율 99.7%, 진짜 오탐률 5.0% / AI 판정: AI 재현율 98.1%, 진짜 오탐률 1.0%) |
| 히트맵에 조각 경계 이음매 (256px 조각을 겹침 없이 나눔) | 조각을 겹치게 배치. 그래도 격자 무늬가 남아서, 조각 가장자리로 갈수록 가중치를 줄이는 Hann 창으로 섞음 | 이음매 제거 |
| 데모 화면에서 모델 버전을 알 수 없음 | 데모 상단에 버전, epoch, 개발 기록 위치 표시 (`--version`) | |

새 임계값을 적용한 테스트 결과입니다(원본 해상도).
- 진짜 판정 비율: 통과 95.3%, 의심 3.7%, AI 1.0%
- 학습 생성기 AI 재현율: 의심 이상 81.1%, AI 판정 69.8%
- hold-out 생성기 AI 재현율: 의심 이상 53.1%, AI 판정 31.6%

데모 조건(짧은 변 512)에서는 진짜의 21.1%가 의심 이상으로 판정됩니다(의심 13.3%, AI 7.9%). 실제 사진이 자주 "의심"으로 나올 수 있다는 뜻이므로, 시연할 때 이 한계를 함께 설명해야 합니다.

## 실험: RDD — 학습 없는 복원 기반 탐지 (2026-11-23, 채택하지 않음)

### 시도한 이유

v2가 폰 사진을 AI로 판정하는 원인은, 학습한 진짜가 COCO뿐이라서 생긴 데이터셋 지름길입니다. 진짜 데이터를 학습하지 않는 training-free 방법이라면 이런 지름길이 원리적으로 생기지 않는다고 보고 시도했습니다.

참고 논문: Choi et al., "A Debiased Reconstruction-based Framework for Training-Free Detection of AI-Generated Images", CVPR 2026.

### 방법 (논문 식 2~4, 이미지 수준 점수만 구현)

- **f_AE(x)**: 이미지를 Stable Diffusion VAE로 인코딩했다가 디코딩한 뒤, 원본과의 LPIPS 거리를 잽니다. AI 이미지는 복원이 잘 되어 값이 작고, 진짜 사진은 값이 큽니다.
- **S_image(x) = f(x) − f(F(x)) − λ·(f(R(x)) − f(F(R(x))))**: 배경이 단순한 진짜 사진도 복원이 잘 되는 편향을, 저역 필터 F(3×3, σ=0.8)와 90° 회전 R로 상쇄합니다. λ=0.5입니다.
- **우리 구현의 범위**
  - VAE는 SD1.4 하나만 썼습니다. 논문은 SD1.4, SD2-base, MiniSD 3개를 앙상블하는데, SD2-base는 로그인 없이 받을 수 없었습니다.
  - 잠재 공간 점수(UNet 노이즈 예측 오차)는 구현하지 않았습니다.
  - 입력은 원본 해상도 중앙 크롭입니다(팀 데이터 512, Defactify 256).
- **LPIPS 변형**: 전체 층과 VGG 2번째 층(AEROBLADE 방식)을 모두 측정했습니다.
- **JPEG 조건**: 팀 AI 이미지는 PNG이고 폰 사진은 JPEG입니다. 압축 여부만으로 갈리는 것을 막기 위해, AI 이미지를 JPEG 품질 90으로 다시 저장한 조건도 함께 측정했습니다.

### 결과

**팀 데이터** (진짜 605장 vs AI 360장). "진짜 오탐"은 AI 이미지의 90%를 잡는 임계값에서 진짜를 AI로 판정한 비율입니다.

| 방법 | AI 이미지 PNG: AUC | 진짜 오탐 | AI 이미지 JPEG90: AUC | 진짜 오탐 |
|---|---|---|---|---|
| f_AE (LPIPS 전체) | 0.890 | 22.8% | 0.842 | 30.9% |
| S_image (LPIPS 전체) | 0.745 | 48.9% | 0.632 | 61.5% |
| f_AE (VGG 2층) | 0.834 | 31.2% | 0.752 | 44.3% |
| S_image (VGG 2층) | 0.892 | 20.2% | 0.724 | 57.2% |
| **v2 CNN** | **0.979** | **4.6%** | **0.971** | **7.3%** |
| v2 + S_image(VGG 2층) 순위 평균 | 0.990 | 1.7% | 0.939 | 21.0% |

**Defactify 테스트 일부** (COCO 진짜 500장, 각 생성기 300장, 256 크롭). 생성기별 AUC입니다.

| | SD2.1 | SDXL | SD3 | DALL·E 3 | Midjourney |
|---|---|---|---|---|---|
| RDD 최고 점수 | 0.660 | 0.679 | 0.725 | 0.514 | 0.678 |
| v2 (원본 해상도) | 0.989 | 0.995 | 0.992 | 0.897 | 0.949 |

출처: `$CVTP_DATA_ROOT/rdd_results/` (로컬 전용). 실험 코드는 로컬 브랜치 `exp/rdd`(`rdd.py`, `scripts/eval_rdd.py`)에 있습니다.

### 해석

- **JPEG에서 신호가 무너집니다.** AI 이미지를 JPEG로 다시 저장하자 가장 좋은 S_image의 AUC가 0.892에서 0.724로 떨어졌습니다. 이미지 수준 복원 오차는 압축이 없는 이미지에서만 강한 신호입니다. 중고거래 사진은 항상 JPEG로 올라가므로, 이 성질이 이번 용도에는 치명적입니다. Defactify가 무작위 수준(0.51~0.73)인 것도 이미지가 전부 JPEG이기 때문으로 보입니다.
- **논문의 보정이 항상 도움이 되지는 않았습니다.** VGG 2층에서는 개선됐지만(PNG 기준 0.834 → 0.892), 전체 LPIPS에서는 오히려 나빠졌습니다(0.890 → 0.745).
- **폰 기종 편향도 있습니다.** iPhone 16 Pro 사진은 JPEG 조건에서 92%를 AI로 판정했습니다. training-free라도 폰의 영상 처리에 따른 편향에서 자유롭지 않습니다.
- **결합도 도움이 되지 않았습니다.** v2와 결합하면 PNG 조건에서는 좋아 보이지만(오탐 1.7%), 이는 압축 차이 덕분이고 JPEG 조건에서는 v2 단독보다 나빠졌습니다(7.3% → 21.0%).
- **한계**: 논문 방법 중 일부만 구현했습니다(VAE 1개, 잠재 점수 없음). 전체 구현이면 결과가 나아질 수 있습니다. 하지만 JPEG에서 이미지 수준 신호가 사라지는 것은 방법 자체의 성질이라, 전체를 구현해도 이번 용도에서 v2를 넘기는 어렵다고 판단했습니다.

### 결론

**채택하지 않았습니다.** 대신 v2를 팀 데이터로 측정하는 과정에서 v2의 순위 분리 성능은 충분히 높고(JPEG 조건 AUC 0.971), 문제가 진짜 폰 사진의 점수 수준에 있다는 것을 확인했습니다. 다음 단계는 진짜 폰 사진을 학습에 넣는 것(재학습) 또는 점수를 재보정하는 것입니다.

## v3 — 공개 데이터와 팀 데이터를 섞은 학습 (2026-11-23 ~)

### 바꾼 점과 이유

v2까지 "진짜"는 COCO 웹 사진뿐이었습니다. 그래서 모델은 "AI인가"가 아니라 "COCO 같은가"를 배웠습니다. v3는 진짜와 가짜 모두에 **중고거래와 가까운 출처**를 넣습니다. 모델, 전처리, 증강은 v2와 같아서 데이터 효과만 볼 수 있습니다.

| | 학습 | 검증 | 평가 전용 |
|---|---|---|---|
| 진짜: COCO (Defactify) | 6,933 | 1,467 | 2,916 |
| 진짜: FraudBench 아마존 후기 상품 사진 | 1,399 | 196 | 405 |
| 진짜: 팀 폰 사진 | 355 (4명) | 121 (4명의 다른 물건) | **219 (taei, YooJaehwan)** |
| 가짜: Defactify | 6,921 (SD2.1/SDXL/SD3) | 1,471 | 7,336 (DALL·E 3, MJ 포함) |
| 가짜: FraudBench | 2,868 (grok, qwen×2, wan2.7) | 408 | 1,014 (**gpt-image-2, nano-banana-2** 포함) |
| 가짜: 팀 AI 이미지 | 180 | 60 | 120 (평가용 2명의 물건) |

- **누수 방지**: `group_id` 단위로 split을 나눴습니다. FraudBench는 진짜와 그것으로 만든 가짜를 같은 후기 번호로 묶었고, 팀 사진은 촬영자와 물건 단위로 묶었습니다. 평가 전용 생성기는 평가용 후기 묶음에만 넣었습니다.
- **출처 균형**: 학습 샘플러가 클래스 안에서 출처별 비중을 고정합니다. 진짜는 COCO 40%, FraudBench 35%, 팀 25%이고, 가짜는 Defactify 40%, FraudBench 45%, 팀 15%입니다. 팀 사진은 학습 데이터의 2%뿐이라, 균형을 맞추지 않으면 거의 학습되지 않습니다.
- **형식 지름길 제거**: PNG인 가짜(FraudBench의 약 70%, 팀 AI 이미지 전부)는 품질 85~95의 JPEG로 바꿨습니다. 학습 전 지름길 검사에서 JPEG 양자화 테이블의 AUC는 0.47로 단서가 아니었습니다.
- **남은 지름길**: 크기와 비율 메타데이터만으로 학습 생성기를 AUC 1.0으로 맞힐 수 있었습니다("정사각형인가" 하나로 0.933). 원본 해상도 크롭이 크기·비율 정보를 차단하지만, 크롭 안의 물체 크기 차이는 남습니다.

- **A. 진짜 폰 사진**: 평가용 촬영자 2명의 진짜 사진 중 AI 확률 30% 미만이 **90% 이상**

## B 대응: CLIP 백본 (2026-11-23)

### 방법

- **특징 추출**: CLIP ViT-L/14(`openai/clip-vit-large-patch14`)를 학습하지 않고 고정한 채 이미지 특징(768차원, 정규화)을 뽑습니다. CLIP 기본 전처리(짧은 변 224, 가운데 224 크롭)를 씁니다.

## A 대응: v4 — 짝 데이터 (2026-11-23)

### 방법

- 학습·검증에 쓰는 진짜 이미지에서 원본 해상도 512×512 조각을 잘라냅니다. 팀 폰 사진은 4조각, FraudBench는 2조각, COCO 2,500장은 1조각입니다.
- 각 조각을 Stable Diffusion 1.4 VAE로 인코딩·디코딩한 복원본을 가짜로 둡니다.
- 원본 조각과 복원본은 둘 다 JPEG 품질 92로 저장합니다. 짝은 원래 이미지의 `group_id`와 split을 그대로 따라서, split을 넘나들지 않습니다.
- 결과적으로 짝 사이의 차이는 생성(디코딩) 흔적뿐입니다. 장면, 기종, 압축으로는 구분할 수 없으므로, 모델이 기종이나 장면 대신 생성 흔적을 배우게 됩니다.
- 만든 양은 학습 6,293쌍, 검증 1,301쌍입니다. 짝 하나를 눈으로 확인했는데, 같은 장면이고 세밀한 질감만 미세하게 달랐습니다.
- 출처별 비중은 진짜가 COCO 30%, FraudBench 25%, 팀 20%, 짝(진짜) 25%이고, 가짜가 Defactify 30%, FraudBench 30%, 팀 10%, 짝(가짜) 30%입니다.
- 모델, 증강, 평가 데이터는 v3와 같습니다(`configs/model1_aligned_v4.yaml`, `scripts/prepare_aligned_pairs.py`).

### 중지와 재실행

- 첫 실행은 epoch 1을 마친 뒤(검증 F1 0.781) **시스템 메모리(RAM 31GB) 부족으로 중지**됐습니다. 개선한 CLIP 실험(전체 데이터, 다중 조각)도 특징 추출 중에 같은 이유로 중지됐습니다.
- 원인은 두 작업을 동시에 돌린 것입니다. CLIP 추출은 한 번에 32장씩, 최대 4,800만 화소인 폰 사진을 원본 크기로 메모리에 올리고 있었습니다. 같은 시간에 학습 데이터 로더의 워커 4개도 큰 사진을 읽고 있었습니다.
- 재실행에서는 **한 번에 하나씩** 돌렸습니다. 데이터 로더 워커는 2개로 줄였고(`num_workers: 2`), CLIP 배치는 8로 줄였습니다. 중지된 첫 실행의 결과는 `outputs/model1/aligned_v4_killed_epoch1`에 남겨 두었습니다.

### 학습 (재실행)

- 15 epoch를 끝까지 학습했고, 최적 epoch는 15입니다. 검증 F1 0.970, 검증 손실 0.107입니다. epoch당 약 8~9분 걸렸습니다.
- 검증셋에 짝 데이터(1,301쌍)가 섞여 있어서, 이 F1은 v3(0.968)와 직접 비교할 수 없습니다.

### 결과 (데모 조건, 임계값: 의심 0.589, AI 0.849)

| 기준 | v3 CNN | v4 CNN (짝 데이터) | CLIP |
|---|---|---|---|
| A. 평가용 촬영자의 진짜 중 30% 미만 (목표 90%) | 23.3% | **32.9%** | 84.5% |
| B. 새 생성기를 의심 이상으로 탐지 (목표 80%) | 64.7% | **61.8%** | 76.0% |

**진짜 사진의 30% 미만 비율** (괄호는 v3): COCO 80.3% (77.7%), FraudBench 77.5% (80.0%), YooJaehwan 62.0% (50.0%), **taei 8.4% (0.8%)**. taei 사진의 12.6%는 여전히 AI로 판정됩니다(v3 42.0%).

### 해석

- **짝 데이터는 기종 문제를 일부만 줄였습니다.** iPhone 13 mini는 50%에서 62%로, iPhone Air는 0.8%에서 8.4%로 나아졌고, iPhone Air가 AI로 판정되는 비율은 42%에서 12.6%로 줄었습니다. 그래도 기준(90%)과는 거리가 멉니다.
- **원인 추정**: 짝 데이터는 "같은 장면에서 VAE 흔적만 다른" 예시를 주지만, 학습에 쓴 폰 기종(4명)과 평가 기종(iPhone Air, iPhone 13 mini)의 영상 처리 차이 자체는 여전히 학습에 없습니다. CNN은 픽셀 수준 흔적을 보기 때문에, 처음 보는 기종의 처리 흔적을 계속 "다르다"고 읽는 것으로 보입니다.
- **새 생성기 탐지는 오히려 조금 나빠졌습니다**(B 64.7% → 61.8%). 짝 데이터의 가짜가 SD1.4 VAE 흔적 하나뿐이라, 모델이 그 흔적에 집중하면서 DALL·E 3·Midjourney처럼 다른 구조의 생성기에는 덜 반응한 것으로 보입니다.
- **결론**: A, B 모두 미달이고 CLIP보다 크게 낮습니다. 계획대로 CLIP 개선판으로 넘어갑니다.

## 추가 개선 시도: CLIP 중간층 특징과 사진 전체 덮기 (2026-11-23)

### 방법 (`scripts/clip_layers.py`)

- **중간층 특징**: CLIP의 24개 블록마다 CLS 토큰을 저장합니다. 마지막 출력은 의미 위주라 생성 흔적이 지워지는데, 앞쪽 블록에는 낮은 수준의 흔적이 남는다는 아이디어입니다(RINE 계열 연구). 12, 16, 20층, 8~24층 5개, 24층 전체를 각각 표준화한 뒤 선형 분류기를 학습했습니다. 학습 데이터는 최종 모델과 같습니다.
- **사진 전체 덮기**: 기존에는 가운데 224 정사각형만 봤습니다. 짧은 변 224 이미지의 양쪽 끝 크롭도 채점해 로짓을 평균(mean3)하거나 최댓값(max3)으로 합쳤습니다. 가운데 크롭 점수는 기존 최종 모델과 정확히 같은지 확인했습니다.

### 해석

- **중간층은 생성기 계열에 따라 정반대입니다.**
  - FraudBench의 처음 보는 생성기(nano-banana-2 0.99, gpt-image-2 0.93)와 진짜 사진(폰, 상품 사진)에서는 최종 출력보다 훨씬 좋습니다.
  - 반면 DALL·E 3는 12층에서 AUC 0.34로, 진짜보다 오히려 더 진짜처럼 봅니다. 중간층이 Stable Diffusion 계열 디코더의 흔적을 배웠는데, DALL·E 3와 Midjourney에는 그 흔적이 없기 때문으로 보입니다.
  - 앞쪽 층일수록 이 경향이 강합니다.
- **검증 손실로는 이 실패를 잡을 수 없습니다.** 검증셋에는 학습한 생성기만 있어서, 가장 일반화가 나쁜 12층이 검증 손실로는 가장 좋습니다(0.042).

### 평가셋을 보지 않는 선택 (`scripts/clip_layers_select.py`)

선택 기준은 두 가지이고, 학습·검증용 데이터만 씁니다.

1. **같은 계열의 새 생성기**: Defactify와 FraudBench에서 생성기를 하나씩 빼고 학습합니다(4가지 조합). 그다음 검증셋에서 뺀 생성기의 AUC를 봅니다.
2. **다른 계열의 새 생성기**: Defactify 원본의 검증 split에서 DALL·E 3 이미지 400장을 꺼냈습니다. 이 이미지들은 v3에 없었고, v3 학습·평가셋과 같은 캡션은 제외했습니다. 검증셋의 진짜 사진과 비교한 AUC를 봅니다.
   - 이 때문에 이후의 DALL·E 3 평가 수치는 완전히 처음 보는 결과가 아닙니다. Midjourney, gpt-image-2, nano-banana-2는 계속 평가 전용입니다.

규칙은 "두 AUC 중 낮은 쪽이 가장 높은 후보"입니다. 후보에는 최종 출력 + 중간층 로짓을 50:50으로 평균한 결합도 넣었습니다(비율은 고정, 튜닝하지 않음).

| 후보 (mean3) | 같은 계열 AUC | DALL·E 3 AUC | 선택 점수 |
|---|---|---|---|
| 최종 출력 | 0.967 | 0.931 | 0.931 |
| 12층 / 16층 / 24층 전체 | 0.991 / 0.988 / 0.990 | 0.315 / 0.519 / 0.715 | 낮음 |
| 20층 | 0.979 | 0.915 | 0.915 |
| **최종 + 20층 (선택됨)** | 0.985 | 0.933 | **0.933** |
| 최종 + 16층 | 0.991 | 0.643 | 0.643 |

DALL·E 3 선택 세트는 평가셋에서 본 실패(12·16층)를 평가셋 없이 정확히 걸러 냈습니다.

**선택된 "최종 + 20층, mean3"의 평가 결과** (임계값 의심 0.456, AI 0.833)

| | 기존 최종 | 최종 + 20층 |
|---|---|---|
| A. 폰 사진 30% 미만 | 84.5% | **86.8%** (YooJaehwan 79.0%, taei 93.3%) |
| B. 새 생성기 의심 이상 | 76.0% | **67.5%** |
| FraudBench 진짜 30% 미만 | 64.2% | **92.1%** |
| 평가 전용 생성기 AUC 평균 | 0.906 | **0.927** |
| DALL·E 3 / MJ / gpt-image-2 / nano-banana-2 AUC | 0.924 / 0.912 / 0.881 / 0.905 | 0.913 / 0.884 / 0.934 / 0.976 |

- **순위를 매기는 능력(AUC)은 평균적으로 좋아졌습니다.** 진짜 상품 사진의 오탐도 크게 줄었습니다.
- **하지만 B는 떨어졌습니다.** 의심 임계값은 검증셋 AI 이미지의 95%를 잡도록 계산됩니다. 그런데 이 결합은 학습한 생성기 이미지에 더 높은 점수를 주므로, 처음 보는 생성기(특히 DALL·E 3 59.5%, Midjourney 60.3%)가 그 기준 아래로 더 많이 떨어집니다.
- 선택 점수 차이(0.933 대 0.931)도 오차 범위 수준입니다.

### 결론

- **배포 모델은 바꾸지 않습니다.**
  - "최종 + 20층"은 미탐이 늘어(B 76.0% → 67.5%) "미탐이 더 위험하다"는 원칙과 충돌합니다.
  - "최종 출력 + mean3"(A 88.1%, B 75.5%)는 비용이 거의 없는 개선 후보입니다. 하지만 평가셋 결과를 보고 고르면 사후 선택이 되므로, 새 폰 사진으로 확인한 뒤 적용합니다.
- **핵심 병목은 검증 데이터입니다.** 학습한 생성기 계열만으로는 "처음 보는 생성기에 강한가"를 고를 수 없다는 것이 이번 실험으로 드러났습니다. 다른 계열 생성기 이미지 400장(DALL·E 3)만 넣어도 나쁜 후보를 정확히 걸러 냈습니다. 그래서 다음 개선은 모델보다 **데이터**입니다.
  - 학습용으로 최신 생성기(GPT, Gemini, Midjourney 등)의 중고 물건 이미지를 모읍니다.
  - 선택·평가용으로 학습에 없는 기종의 폰 사진을 모읍니다.

## 시스템 차원의 정리 (기준 미달에 대한 대응)

모델 1 하나로는 두 기준을 함께 맞추지 못했습니다. 그래서 서비스 안에서 모델 1의 역할을 다음과 같이 정합니다.

1. **1차 선별기로 씁니다.** 모델 1의 판정은 최종 판정이 아니라 위험도 표시입니다.
   - "AI"는 강한 경고입니다. 진짜 폰 사진의 오탐은 평가셋에서 0%였습니다.
   - "의심"은 추가 확인 대상입니다. 판매자에게 다른 각도의 사진을 요청하거나 사람이 검토합니다.
   - "통과"도 "AI가 아님을 보장"하지 않는다고 화면에 명시합니다. 데모 안내 문구에 이미 들어 있습니다.
2. **모델 2(인증샷 메모 판별)와 함께 씁니다.**
   - AI 생성기는 판매자의 닉네임과 날짜가 적힌 손글씨 메모를 실제 물건과 함께 자연스럽게 만들기 어렵습니다. 그래서 메모 확인은 모델 1이 놓치는 최신 생성기 이미지를 보완하는 독립된 신호가 됩니다.
   - 권장 규칙은 다음과 같습니다.
     - 모델 1이 "AI" → 경고
     - 모델 1이 "의심"이고 메모 확인 실패 → 경고
     - 모델 1이 "의심"이고 메모 확인 통과 → 주의 표시
     - 그 밖 → 통과
   - 결합 규칙의 실제 성능은 모델 2와 같은 사진 세트로 측정해야 하며, 아직 측정하지 않았습니다.
3. **메타데이터는 모델에 넣지 않고 참고 정보로만 씁니다.**
   - EXIF의 카메라 제조사·기종이 있으면 화면에 보조 정보로 보여 줄 수 있습니다.
   - 하지만 모델 입력으로 쓰지는 않습니다. 이 프로젝트의 지름길 검사에서 크기·형식·출처 메타데이터가 가장 큰 지름길이었습니다(v1~v3). 또 EXIF는 쉽게 지우거나 위조할 수 있고, 메신저나 중고거래 앱이 업로드할 때 지우는 경우도 많습니다.
4. **임계값은 팀이 데모에서 조정할 수 있습니다.**
   - 평가셋으로 진단한 결과, CLIP은 판정 경계를 0.35 근처로 옮기면 두 기준을 모두 넘는 지점이 있었습니다(앞 "진단" 절).
   - 하지만 이 값은 평가셋을 보고 고른 값이라 성능으로 주장할 수 없습니다. 정당하게 확인하려면 학습·검증에 쓰지 않은 **새 기종의 폰 사진을 더 모아** 다시 평가해야 합니다. 이것이 가장 우선인 다음 작업입니다.

### 남은 한계와 다음 작업

- 평가용 폰 사진은 2명, 2기종(219장)뿐입니다. 기종별 수치의 오차가 큽니다.
- 학습하지 않은 생성기 탐지(B)는 76%입니다. 최신 생성기가 계속 나오므로, 새 생성기 이미지를 주기적으로 학습 데이터에 추가해야 합니다. CLIP 방식은 분류기 하나만 다시 학습하면 되어 몇 분이면 끝납니다.
- CLIP은 사진 가운데 정사각형만 봅니다. 가장자리만 합성한 사진은 놓칠 수 있습니다.
